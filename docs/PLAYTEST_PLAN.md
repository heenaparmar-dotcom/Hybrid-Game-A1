# RHYTHM RUSH: Playtest Plan

A practical script for a real playtest with **3 to 5 consenting people** aged about 18 to 24. **Nothing in this file is a result.** Every table is blank on purpose. Fill them in only with what you actually see and hear.

## 1. Set up

- One phone and one laptop, both opened to the hosted game (so challenge links work between devices).
- 2 metres of clear floor and one chair.
- A stopwatch (phone timer), this sheet, a pen. Do not record video or audio unless the participant agrees.
- Participants are coded P1, P2, ... Do not write full names.

**Read aloud before starting**
- "This tests the game, not you. You can stop, skip or sit at any time without explaining why."
- "I will not coach you. If you are stuck, say so, and I will write it down."
- "Is there any movement you would rather not do? There is a seated version."

## 2. Session script (about 20 minutes)

| Step | Min | What the facilitator does |
| --- | --- | --- |
| Welcome and consent | 3 | Read the text above. Do not explain the game. |
| **Unassisted start** | 8 | Say only: "Open the game and play." Watch silently. Note every hesitation over 10 seconds and every question. |
| Quick interview | 4 | Questions in section 5. |
| **Challenge task** | 4 | "Make a puzzle for a friend, copy the link, and open it on the other device." |
| Wrap-up | 1 | Thank them. Ask for any other comments. |

## 4. Timing and the digital / physical balance

The assignment describes a hybrid game with a physical half and a digital and social half. This is the **design intent**, and it has not been validated.

Time, with the stopwatch, for each level a participant plays:

| Level | Puzzle (s): from the puzzle appearing to "You got it" | Invitation and set-up (s) | Dance (s): music start to celebration | Notes |
| --- | --- | --- | --- | --- |
| P_ L1 | | | | |
| P_ L2 | | | | |
| P_ L3 | | | | |

Then time the social task once per participant:

| Participant | Make a puzzle and copy the link (s) | Open it on the other device and reach the puzzle (s) |
| --- | --- | --- |
| P1 | | |

**Physical share** = dance seconds / (puzzle + invitation + dance + social seconds). Record it per participant, and discuss it with the team before judging. Write down your own target range **before** the session (for example "at least a third of a level should be physical"). The planned dance length is 39 to 42 seconds including the count-in, so the puzzle length decides the balance; if puzzles take much longer than the dance, consider shorter lines or longer routines, then re-test.

## 5. Interview questions

Ask open questions and write the answer in their own words.
1. What did you think you were meant to do when you opened the game?
2. Was the puzzle too easy, too hard or about right? Why?
3. How did the dance feel (enjoyable, awkward, too short, too long, easy to follow)?
4. Did you know what to copy and when? Was anything unclear?
5. Would you send a puzzle to a friend? What would make you more or less likely to?
6. Did the Hindi level work for you?
7. What is the one thing you would change first?

Rate 1 (strongly disagree) to 5 (strongly agree):

## 7. After the session

1. Copy your notes into the **Iteration log** in `docs/ASSIGNMENT_DOCUMENTATION.md`: issue, evidence, change, retest result.
2. Make at least one change driven by what a real person did or said. Then re-test it with at least one person (or repeat the failing task) and record the result honestly, including if it did **not** fix the problem.
